Agent Infra 在今天最成功的时候，也是在未来最可疑的时候。

Planner、Router、Reflection、Critic，都是模型能力不足时很自然的产物。模型不能稳定规划，规划被拆出来。模型不能稳定调用工具，路由被拆出来。模型输出不稳定，复核被拆出来。

模型的缺口，逐渐变成了系统的模块。

模块一旦进入生产，就会拥有自己的 state、trace、eval、owner 和 roadmap。它开始脱离最初的原因。模型后来变强了，模块继续存在，因为周围已经长出了依赖。

这类系统有一个奇怪的时间关系。

模型的问题是短期的。
系统的维护是长期的。

很多 Agent 架构真正服务的，不是业务复杂度，而是某个模型版本的能力边界。模型的版本在变，架构通常不变。于是一次能力升级，删除的不是一段 prompt，而是一层原本被认真设计过的 infrastructure。

权限、交易、审计、业务状态、私有数据、工具副作用，不属于这个问题。它们来自现实世界，不来自模型的不足。模型再强，也不会让权限边界自己出现，不会让一笔已经提交的交易自动变得幂等。

这些东西有自己的重量。

Planner 没有。

一个没有权限边界、没有并发需求、没有 context isolation 的 Multi-Agent 系统，很难和“几个模型轮流说话”区分开。角色变多以后，系统看起来更像组织，也更像未来。token 和 latency 也一起变多。

复杂度经常被误认成智能。

很多 Agent Infra 的生命周期，可能比它的 roadmap 短。它们不是未来架构。它们只是当前模型的兼容层。
